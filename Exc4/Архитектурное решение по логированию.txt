Логирование:
 - DEBUG применяется в окружении DEV для тестирования системы, логи в режиме DEBUG должны показывать промежутучные результаты вычислений.
- INFO изменения статуса заказа с какого на какой, пользователь, ид заказа, время выполнение методла API
- ERROR ошибки при выполнении запроса пользователя, логируем стэктрейc ошибки, ИД заказа и ИД пользователя.
- ERROR ошибка при выполнении отложенных заданий воркерами/джобами, логируем стэктрейc и ИД заказа.
 - WARN ошибки авторизации пользователей

Мотивация:
 - улучшение видимости и повышение безопасности системы
 - более быстрое решение проблем
 - логирование поступаемых входных/выходных данных.
 - доступность промежуточных результатов вычислений в бизнес логике.

 Предлагаемое решение:
 1. Требуется внедрить зависимость бибилиотеки LOG4J для микросервисов Spring Boot и Log4CSharp C#.
 2. В код сервисов, ососбенно в сложной витьеватой логике, залогировать состояние сущностей и их свойтств.
 3. С помощью LOGSTASH обеспечить транспортировку содержимого логов в Хранилище, OpenSearch.
 4. Логи должны записываться в файл в ввиде JSON  с использованием JsonEncoder.
 5. Персональные данные, такие как ФИО, Емаил , Номер телефона должны маскироваться, напрмер ***Sv@mail.ru, +7920***7771
 6. Хранение файлов должно ограничиваться 2 дня, размер файла логов не должен превышать 10 МБ.
 7. В OpenSearch логи храняться в индексе в течение 1 года.
