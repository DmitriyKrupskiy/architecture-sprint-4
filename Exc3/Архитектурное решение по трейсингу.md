Исходя из маршрута прохождения заказа, заказ может зависнуть: 
1. После подтверждения заказа и проходение заказа через очередь в MES.
Заказ может повиснуть на долгом расчете стоимости или при неуспешном его завершении. Сценарий 2.
2. Заказ может быть потерян при прикреплении документа с описанием изделия. Сценарий 1.
В контекст трейса требуется добавить ID заказа, ID пользователя, STATUS заказа.
Мотивация
1. Внедрение трейсинга позволит отслеживать:
   Response time (latency) для API магазина.
   Number of HTTP 500 for shop API
   Создание заказов, закончившиеся неуспешно. (фактически потеря заказа).
   Время между изменением статуса заказа, Напрмер Заказ Создан, и Заказ взят в работу Оператором.

Компромиссы: 
1. Использование трейсинга для отслеживания статуса и время пребывания заказа в статусе не будет очень удобен. 
2. Использования трейсинга для отслеживания запросов к внешним сервисам, напрмер, сервис оплаты,
потребует дополнительных доработок на стороне 3d party.

С целью безопасности и выполнения требования законодательства в части конфиденциальных данных, требуется ограничить доступ
к просмотру трейсинга запросов. Только пользователи с ролью Админ или Техническая поддержка должны иметь доступ к просмотру трейсов запроса
среды Продакшн.
